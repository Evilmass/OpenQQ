# 图形化 Bot 与 AI 养鱼

不会写代码也能做自己的 QQ Bot：在 WebUI 里像 Scratch 一样拖积木，规定「收到什么消息 → 怎么判断 → 回复什么」，还能接入 AI，让 Bot 有自己的名字、性格和记忆。

- 入口：WebUI 左侧「Bot → Bot 编程」和「Bot → AI 接入」。
- Bot 运行在 OpenQQ 的主进程里，用的是已经挂接好的 QQ 会话，不需要另外连接 OneBot。
- 所有数据（积木程序、记忆、AI 设置）都保存在本机的 `data/bot/`。

> 控制台的「AI 接入」页顶部有一条标着「广告」的推广位，默认介绍 zelix.asia（API 中转站）。它**只显示在 WebUI 里**，不会发到 QQ，也不会发给 AI；文案、链接和开关都能在同一页修改或关闭，见 [推广位](#推广位)。

## 十分钟上手

1. **填 AI 接入**：打开「AI 接入」，填 Base URL 和 API Key，点「获取模型列表」选一个模型，点「测试连接」，看到「连接成功」后点「保存」。（不用 AI 的 Bot 可以跳过这一步。）
2. **新建 Bot**：打开「Bot 编程」，点「新建 Bot」，选「被 @ 时用 AI 回复」。新建的 Bot 默认是**未启用**的。
3. **看看积木**：「积木」页里已经有两块积木：`当群里有人 @我` → `AI 回复 [消息文本]`。可以从左边的工具箱拖新的积木进来，改完点「保存积木」。
4. **试运行**：切到「测试」页，选「群聊」并勾上「@ 机器人」，输入一句话，点「运行」。这里**不会真的发 QQ 消息**，只会显示 Bot 打算发什么。
5. **启用**：打开页面上方的「启用」开关。之后群里有人 @ 机器人，Bot 就会回复。
6. 没有回复时，先看「测试」页下面的「运行记录」，里面有每次运行的结果和失败原因。

> 启用后收到的消息会真的发到 QQ 里。第一次建议先用自己的小号或测试群，并在「范围与限制」里把 Bot 限定在测试群。

## AI 接入

「AI 接入」页对所有 Bot 共用一份设置：

| 项目 | 说明 |
| --- | --- |
| Base URL | OpenAI 兼容接口的地址，例如 `https://api.example.com/v1`。只写域名会自动补 `/v1`；直接粘贴完整的 `…/v1/chat/completions` 也可以，会自动裁掉后面的部分。不能带账号密码或 `?` 参数。 |
| API Key | 服务商给你的密钥。留空表示「不修改」。 |
| 模型 | 直接输入模型名，或点「获取模型列表」（调用 `GET {Base URL}/models`）后从下拉里选。 |
| 温度 / 最大回复长度 / 超时 | 温度 0–2（每个 Bot 可以在人设里单独设置）；最大回复长度是单次回答最多多少 tokens；超时 5–120 秒。 |
| 测试连接 | 用表单里的内容发一条很小的真实请求（让模型回复 ok），不需要先保存。 |

用中转站（例如 zelix.asia）时，把它给你的接口地址填进 Base URL，把它发的密钥填进 API Key 即可，只要它兼容 `/chat/completions`。本机模型（Ollama、LM Studio 等）也一样，例如 `http://127.0.0.1:11434/v1`，Key 可以留空。

**Key 的保管**

- Key 只写入本机的 `data/bot/ai.json`（Linux 上权限为 0600，已被 `.gitignore` 忽略，不会被提交）。
- 页面和 `/api/bot/*` 接口只会告诉你「已保存」和末 4 位，**任何响应里都不会出现完整的 Key**。接口返回的错误信息会先擦掉 Key 再显示；日志和事件流里也没有 Key。
- 请求只发往你填写的 Base URL，不跟随重定向。非本机、非内网地址必须用 `https://`，否则拒绝保存，避免明文发送 Key。
- 更换了 Base URL 的**服务器地址**时，必须同时重新填写 Key（旧 Key 不会被发给新的服务器）。在同一个服务器上改路径不受影响。
- 访问这些接口仍然需要 WebUI 启动时生成的访问密钥。

## AI 生图

控制台的「AI 生图」页调用 OpenAI 兼容的生图接口（`POST {Base URL}/images/generations`），在页面里预览生成的图片并下载。它和「AI 接入」各存各的设置，互不相通。

| 设置 | 说明 |
| --- | --- |
| Base URL | 默认 `https://api.zelix.asia`（zelix.asia 的接口地址）。只填域名时会自动补上 `/v1`，也可以直接粘贴完整的 `…/images/generations` 地址；规则和「AI 接入」一样，非本机、非内网地址必须用 `https://`。 |
| API Key | 只保存在本机的 `data/bot/image.json`（权限 0600，已被 `.gitignore` 忽略），页面和接口只显示「已保存」和末 4 位。输入框旁边的「点击获取 KEY」会在新标签页打开 https://zelix.asia（中转站由 OpenQQ 维护者运营，你也可以改用任何兼容的服务）。 |
| 模型 | 直接输入，或点「获取模型列表」（调用 `GET {Base URL}/models`）后选择。默认 `gpt-image-1`；具体有哪些生图模型取决于你用的服务。 |
| 图片尺寸 / 张数 / 超时 | 尺寸是 `auto` 或「宽x高」（默认 `1024x1024`，支持哪些取决于模型）；一次最多 4 张；超时 10–300 秒（默认 120）。 |
| 测试连接 | 只读一次模型列表，不会生成图片，也不收费。 |

生成时用表单里的内容，不需要先保存。每次生成都会向接口计费，所以同一时间只会有一个生成任务在进行。接口既可以直接返回图片（`b64_json`），也可以返回图片地址（`url`）：地址由 OpenQQ 在本机下载，不带 Key，只接受不带账号密码的 http(s) 地址，并拒绝指向本机或内网的地址（接口本身就在本机或内网时除外）；下载内容必须是图片（png、jpeg、gif、webp、bmp），每张最多 16 MiB。

在页面里生成的图片只显示在页面里，不会保存到磁盘，也不会发到 QQ；需要的话点「下载」自己保存。外部程序想直接生图（并发到群或好友），用 OneBot 动作 `generate_image`，见 [actions.md](actions.md#生图)；它用的是这一页保存的设置。Key 的其他保管规则（不跟随重定向、换服务器地址必须重填 Key、错误信息先擦除 Key）和「AI 接入」相同。

## 积木怎么用

每个积木堆都以一个「触发」积木开头，下面接着要执行的积木。收到消息时，OpenQQ 检查所有触发积木，条件满足的就运行它下面的整个积木堆（多个触发同时满足，就各自运行一遍）。

操作：从左边工具箱拖积木到画布；把积木拖到另一块的下面或空槽里它就会吸住；拖到右下角的垃圾桶删除；右键积木可以停用、复制；滚轮缩放。积木的输入槽里灰白色的「默认值」可以直接点开修改。

### 触发

| 积木 | 什么时候运行 |
| --- | --- |
| 当收到 [任意/私聊/群聊] 消息 | 每收到一条符合范围的消息 |
| 当群里有人 @我 | 群消息里 @ 了机器人 |
| 当收到 [范围] 消息 [包含/等于/开头是] [关键词] | 关键词可以用 `\|` 分隔写多个，匹配任意一个，不区分大小写 |
| 当收到 [范围] 命令 [/ask] | 消息以这个命令开头（命令后要么结束要么是空白），后面的内容是「命令参数」 |

判断用的是消息里的**文字部分**：@、图片等不算文字。

### 控制与运算

| 积木 | 说明 |
| --- | --- |
| 如果 … 那么 / 如果 … 那么 … 否则 | 条件判断 |
| 重复 N 次 / 当 … 时重复 | 循环，每个循环最多 100 次 |
| 停止本次运行 | 结束当前积木堆 |
| 连接 A 和 B、A 包含 B、A 的长度、替换、第 N 到 M 个字符 | 文字处理（包含不区分大小写） |
| A + − × ÷ 取余 B、随机整数、随机选一个 | 数学；除以 0 得 0；「随机选一个」用 `\|` 分隔候选项 |
| A = ≠ < ≤ > ≥ B、且、或、不满足 | 比较与逻辑；两边都是数字时按数字比较，否则按文字比较 |
| 当前 [小时/分钟/星期几/日期/时间] | 运行 OpenQQ 的这台电脑的本地时间 |

### 消息信息

`消息文本`、`发送者 QQ`、`发送者昵称`、`群号`、`机器人 QQ`、`消息 ID`、`命令参数`，以及判断用的 `是群聊 / 是私聊 / 我被 @ 了 / 含图片`。没有的信息为空。

### 变量

点「新建变量」，用「把变量设为」「把变量增加」和变量积木。变量**只在本次运行内有效**，下一条消息会从头开始。要跨消息保存东西，请用「记忆」积木。

### 发送

| 积木 | 说明 |
| --- | --- |
| 回复 [文字] @发送者 引用原消息 | 发到收到消息的那个会话。@ 只在群里有效 |
| 发送到 [私聊/群] 号码 内容 | 发给指定的 QQ 号或群 |
| 发送 [图片/语音/视频/文件] 来源 | 来源只能是 `http(s)://` 链接或 `base64://` 数据，**不能是本机路径**（否则群里任何人都可能借积木读取这台电脑上的文件）。格式和大小限制同 [docs/actions.md](actions.md) 的「媒体来源」 |
| 发送 [骰子/猜拳]、发送 QQ 表情 编号 | 发到收到消息的会话 |

### AI

| 积木 | 说明 |
| --- | --- |
| AI 回复 [提问] 记住对话 引用原消息 | 把人设、记忆、近期对话和这句提问一起发给 AI，并把回答**原样**发到当前会话（只按单条消息 4000 字截断，不会附加任何别的内容） |
| 询问 AI [提问] 记住对话 | 只返回 AI 的回答文字，**不会自动发送**。可以拼接后用「回复」发出，或者放进条件判断 |

提问为空时不会调用 AI。AI 失败（Key 不对、超时、限流……）时本次运行中止，不会发送半截消息，原因记在「运行记录」里。

### 记忆

| 积木 | 说明 |
| --- | --- |
| 记住 [名称] 为 [内容] 范围 [当前会话/整个 Bot] | 长期保存一条笔记，也会写进 AI 的提示词 |
| 回忆 [名称] 范围 | 读取笔记，没有记过就是空 |
| 忘记 [名称] 范围 | 删除笔记 |
| 清空当前会话的记忆 | 删除当前会话的对话记录、摘要和笔记 |

笔记名称最长 40 个字符，内容最长 500 个字符，每个范围最多 100 条。

### 内置示例

新建 Bot 时可以选：

- **被 @ 时用 AI 回复**：`当群里有人 @我` → `AI 回复 [消息文本]`（引用原消息）。
- **私聊用 AI 聊天**：`当收到 [私聊] 消息` → `AI 回复 [消息文本]`，每个人的记忆互相独立。
- **关键词自动回复 + 掷骰子**：群里提到「你好」就 @ 对方打招呼；`/roll` 掷 1–6。
- **记住名字**：`/记住 小明` 写入笔记，`/我是谁` 回忆出来。

## 人设与记忆（养鱼）

每个 Bot 都有**自己独立**的人设和记忆，互相看不到。

### 人设

「人设」页可以设置：名字、性格（温柔 / 活泼 / 毒舌 / 严谨 / 佛系 / 自定义）、性格补充（口头禅、习惯）、回复风格（简短 / 适中 / 详细）、系统提示词（最多 4000 字）、可选的温度。

每次调用 AI 时，请求的内容依次是：

1. **system**：系统提示词 → 名字、性格和风格 → 更早对话的摘要 → 已记住的笔记（整个 Bot 的 + 当前会话的）→ 现在的时间和会话类型；
2. 最近的几条对话原文（条数在「记忆」页设置，群聊里每条用户消息前带发言人的昵称）；
3. 这一次的提问。

提示词里只有人设、记忆和对话，没有别的内容。

### 记忆

记忆按**会话**分开保存：每个群、每个私聊对象各一份（`g:群号`、`p:QQ号`），群聊和私聊不会串。「记忆」页可以查看每个会话的摘要和近期对话、查看 Bot 笔记、导出 JSON、清空。

| 数据 | 内容 | 上限 |
| --- | --- | --- |
| 近期对话 | 最近的对话原文 | 超过 40 条时把最旧的折进摘要，只留 24 条；硬上限 100 条；每条最长 2000 字 |
| 摘要 | 更早对话的浓缩 | 1500 字，满了丢最旧的行 |
| 笔记 | 积木「记住」写入的内容 | 每个范围 100 条，名称 ≤ 40 字、内容 ≤ 500 字 |
| 会话个数 | | 200 个，超过时淘汰最久没有更新的 |
| 整个文件 | `memory.json` | 2 MiB，超过时淘汰最久没有更新的会话 |

摘要方式有两种：**规则摘要**（默认，不额外调用 AI：每句截成一行保留）和 **AI 摘要**（折叠时额外调用一次 AI 来合并摘要，失败自动回退到规则摘要）。

「记住对话」开关关闭后，Bot 不再记录新的对话，也不会把历史带给 AI；积木「记住 / 回忆」的笔记不受影响。

「测试」页的试运行使用单独的「测试会话」，和真实会话的记忆分开，可以在「记忆」页清掉。

## 推广位

「AI 接入」页顶部有一条推广位，**默认介绍 zelix.asia（API 中转站，由 OpenQQ 维护者运营）**。它只是控制台界面上的一条横幅，**不会发送到 QQ，不会出现在 Bot 的任何回复里，也不会进入发给 AI 的提示词**。

同一页下方的「推广位」卡片可以修改它：

- **开关**：关闭后横幅不再显示。
- **文案**：最多 300 个字，可以改成任何内容。
- **链接**：可选，只接受 `http://` 或 `https://` 网址；显示为「了解更多」按钮，在新标签页打开。留空则不显示按钮。
- **预览**：卡片里实时预览横幅的样子。「恢复默认」改回 zelix.asia 的介绍。

横幅上的「广告」标记是写死在界面里的，不能通过设置去掉，让人一眼看出这是推广内容。设置保存在 `data/bot/ads.json`，是全局的，不属于某个 Bot。默认是开启的；想默认关闭，改 `src/bot/ads.mjs` 里 `defaultAds()` 的 `enabled`。

## 限制与安全

积木程序保存在本机，由 OpenQQ 主进程里的解释器执行。解释器只认固定的一组积木（白名单），**不使用 `eval` 或 `new Function`**，也不能访问文件、网络或进程。

| 限制 | 默认值 | 说明 |
| --- | --- | --- |
| 单次运行步数 | 2000 | 超过视为死循环，强制停止 |
| 单次运行时间 | 60 秒 | 包括等待 AI 的时间 |
| 循环次数 | 100 次 | 每个循环 |
| 单次运行发送条数 | 5 条 | |
| 文字长度 | 20000 字（单条消息 4000 字） | 防止拼接文字撑爆内存 |
| 每分钟发送条数 | 20 | 每个 Bot，可在「范围与限制」里改（1–120），超过后本次运行中止 |
| 每分钟调用 AI | 10 | 每个 Bot，可改（1–60） |
| 触发间隔 | 2 秒 | 同一个人在同一会话里连续触发，间隔内的消息被忽略（0–60） |
| 积木数量 | 600 块 / 40 堆 / 200 KiB | 编辑器里最多 300 块 |
| Bot 数量 | 20 | |

其他：

- **适用范围**：每个 Bot 可以分别设置私聊和群聊「全部 / 只在名单内 / 名单内除外」。
- 同一个 Bot 在同一个会话里的运行按顺序执行；同时运行的总数有上限，超过的会被跳过并记录。
- 同步历史消息期间和超过 2 分钟的旧消息不会触发 Bot。
- Bot 自己发的消息不会再触发 Bot，所以不会自己和自己对话。
- 保存时服务端会重新校验整个程序（积木类型、字段取值、数量、深度），不合格的程序保存不进去。
- 试运行不会发送任何 QQ 消息。

## 数据位置与备份

| 路径 | 内容 |
| --- | --- |
| `data/bot/ai.json` | Base URL、**API Key**、模型等（权限 0600，不要提交、不要分享） |
| `data/bot/ads.json` | 推广位的文案、链接和开关（全局，只用于界面显示） |
| `data/bot/bots/<id>/bot.json` | 一个 Bot：积木程序、人设、记忆设置、范围、限制 |
| `data/bot/bots/<id>/memory.json` | 这个 Bot 的记忆 |

`data/` 已被 `.gitignore` 忽略。可以用环境变量 `OPENQQ_DATA_DIR` 换成别的目录。备份就复制整个 `data/bot/`（注意其中的 `ai.json` 含 Key）。

Docker：`compose.yaml` 已经把 `./docker-data/data` 挂载到容器的 `/app/data`，重建容器不会丢失 Bot 和记忆。

## 常见问题

**没有回复？** 打开 Bot 的「测试」页看「运行记录」。常见原因：Bot 没启用；触发条件没满足（群里没有 @、关键词不对、范围里没选这个群）；AI 没配置或 Key 失效；被限流；QQ 还没登录完成。

**AI 报错 HTTP 401 / 404？** 401 通常是 Key 不对；404 通常是 Base URL 少了 `/v1` 或多了路径。先在「AI 接入」页点「测试连接」。

**想让 Bot 说话更像某个人？** 在「人设」页写系统提示词，再用「性格补充」加几个口头禅；摘要和笔记会在聊天中逐渐积累。

| `store.mjs` | Bot 配置与 AI 设置的落盘 |
| `engine.mjs` | 把事件交给 Bot、限流、发送、记录 |
| `api.mjs` | WebUI 的 `/api/bot/*` 接口 |

`/api/bot/*` 接口（都需要 WebUI 访问密钥）：`GET/POST /api/bot/ai`、`POST /api/bot/ai/test`、`POST /api/bot/ai/models`、`GET/POST /api/bot/bots`、`GET/POST /api/bot/bots/<id>`、`POST …/delete`、`POST …/simulate`、`GET …/runs`、`GET …/memory`、`GET …/memory/chat?key=`、`GET …/memory/export`、`POST …/memory/clear`。

**增加一个积木**：

1. 在 `blocks.mjs` 的 `blockDefinitions` 里加一条定义（Blockly JSON 格式；`style` 选一个已有的 `oq_*` 样式）；
2. 在 `interpreter.mjs` 的 `evaluate()`（有输出的积木）或 `statement()`（语句积木）里加对应的 `case`；
3. 在 `ui/blocks/editor.ts` 的 `toolbox` 里把它放进某个分类；
4. 在 `test/bot-interpreter.test.mjs` 里加测试。

`blocks.mjs` 里的测试会检查每个定义的占位符和参数一一对应；`compile.mjs` 会自动按定义校验新积木的字段，不需要额外改动。

积木编辑器基于 [Blockly](https://developers.google.com/blockly)（Apache-2.0），打包成独立的 `web/blocks.js`，只在打开 Bot 页面时加载；所有脚本、样式和图片都由 OpenQQ 本地提供，不依赖任何 CDN，符合 WebUI 的内容安全策略。
